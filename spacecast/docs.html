Spacecast documentation

Spacecast posts Jira updates into Google Chat spaces through Google Chat incoming webhooks. This guide covers setup, every rule option, the admin settings, and troubleshooting.

1. Requirements

  • Jira Cloud. You need to be a Jira site admin to install Spacecast and to open its settings page.
  • A Google Workspace account with Google Chat. Your Workspace admin must allow incoming webhooks (Google Admin console > Apps > Google Workspace > Google Chat > Chat apps settings).
  • Permission to add webhooks to the Google Chat space you want to notify.

2. Install

  1. Open Spacecast on the Atlassian Marketplace and choose Get it now, or in Jira go to Settings > Apps > Explore more apps and search for Spacecast.
  2. Approve the requested permissions. Spacecast reads Jira issue and user information so it can match your rules and build messages.
  3. After installing, go to Settings > Apps > Spacecast for Google Chat.

Spacecast is free for sites with up to 10 users. Larger sites need an active subscription. If a site is not licensed, the settings page shows a banner and no notifications are sent.

3. Create a Google Chat webhook

  1. In Google Chat, open the space that should receive Jira updates.
  2. Open the space name menu and choose Apps & integrations, then Webhooks (or Add webhooks).
  3. Name the webhook Spacecast so messages are clearly labeled. Optionally set the avatar URL to https://ean-solutions.com/spacecast/logo.png.
  4. Save, then copy the webhook URL. It starts with https://chat.googleapis.com/v1/spaces/.

Treat the webhook URL like a password. Anyone with it can post into the space. Spacecast keeps it in encrypted Forge secret storage and never shows it again after you save. Never send it to support.

4. Create your first rule

A rule connects a set of Jira events to one Google Chat space.

  1. On the Spacecast settings page, choose Add rule (or From template, see templates).
  2. Give the rule a name, for example Team space: bugs.
  3. Paste the Google Chat webhook URL.
  4. Choose which events should send a message and, optionally, narrow it with projects, statuses, people, or JQL.
  5. Save, then press Test. A test card should appear in the space within a few seconds.

From then on, matching Jira updates appear in the space, usually within seconds.

5. Rule options

All filters in a rule must match for a message to be sent. Leave a filter blank to match everything.

Send a message when

  • Issue created: a new issue is created.
  • Status changed: an issue moves to a different status.
  • Assignee changed: an issue is assigned or unassigned.
  • Comment added: someone comments on an issue. Up to 600 characters of the comment are included.
  • Someone mentioned: a user is @mentioned in a comment or description.
  • Other field updates: any other field edit, such as priority or summary.

Project keys

Comma separated project keys, such as ABC, OPS. Blank means all projects.

Only status changes into

Comma separated status names, such as In Review, Done. Applies to Status changed events. Blank means any status.

Only when these people are involved

Pick one or more people, then choose how they must be involved: Assignee, Reporter, Mentioned, or Watcher. For personal notifications, pick yourself and point the rule at a Google Chat space that only you are in.

JQL filter

Any JQL that the issue must match, for example issuetype = Bug AND priority in (High, Highest). Use it for anything the other filters do not cover, such as components, labels, or custom fields.

One thread per issue

On by default. The first message for an issue starts a thread, and later updates to the same issue reply in that thread, so the space stays readable. Turn it off to post every update as a new message.

Compact messages

Sends a single line of text instead of a card: the linked issue key, the summary, and who changed it. Useful for busy spaces.

Delivery

  • Right away (default): one message per update.
  • Hourly digest: at most one message an hour, listing each issue once with what changed (created, moved, assigned, comments).
  • Daily digest: one message a day at the hour and time zone you choose.

Digests include the issue key, summary, and status changes, but never comment text. One thread per issue and Compact messages apply only to messages sent right away. A digest lists up to 30 issues and says how many more changed.

6. Templates

Choose From template on the settings page to prefill a rule:

  • Team space: new issues, status changes, and comments, one thread per issue.
  • Just me: only issues you are assigned to, mentioned in, or watching. Use a space with only you in it.
  • Finished work: only when issues move to Done.

You still add the webhook URL and can change any option before saving.

7. What messages look like

Each message is a Google Chat card. The header shows the issue key and summary, and a line such as Ana moved this bug. The body shows the status (or the change, such as In Progress → Done), the comment text for comments (up to 600 characters), and an Open in Jira button.

8. Project admin self-serve

The setting Let project admins manage rules for their own projects is on by default. Project admins then find Spacecast under Project settings > Spacecast for Google Chat and can create and edit rules that only cover their project. The rule list shows who manages each rule: Site admin or <KEY> admins. Site admins always see and can edit every rule. When a site admin turns the setting off, the project page only says that Spacecast is managed by the Jira site admin.

9. Delivery log

The Recent deliveries table on the settings page lists messages Spacecast sent or failed to send over the last 7 days, with the rule, issue, time, and result. Entries are removed automatically after 7 days.

10. Personal notifications

Each person can get their own updates as direct messages from the Spacecast app in Google Chat, without setting up a space or webhook.

  1. In Jira, open Apps > Spacecast: My notifications.
  2. Click Connect Google Chat and sign in with your Google Workspace account. Google asks to see your email address and to create conversations in Google Chat; Spacecast uses these once, to open your direct message with the app.
  3. Choose what to get: issues assigned to you, mentions, and changes or comments on issues you watch. Optionally limit to certain projects, issue types, and priorities, then click Save.
  4. Click Send a test DM to check that messages arrive.

You never get a message about your own changes or about issues you cannot view, and the text of restricted or internal comments is never shown. To stop, click Disconnect.

Site admins: the setting Let people get their own notifications as Google Chat DMs turns this on or off for the site. The Personal notifications table on the settings page lists who has connected, and Remove deletes a person's link. Your Google Workspace admin may need to allow the Spacecast Chat app.

Personal notifications are rolling out as an app update that a Jira site admin approves.

11. Troubleshooting

Test works but real updates do not arrive

  • Check the rule's filters. Every filter must match: event type, project key, status, people, and JQL.
  • Check that the JQL is valid by running it in Jira issue search.
  • Look in the delivery log. If nothing is listed, the update did not match any rule.
  • Check that the site is licensed. An unlicensed site shows a banner on the settings page.

Test fails

  • Make sure the URL is the full webhook URL copied from Google Chat.
  • If the webhook was deleted in Google Chat, create a new one and edit the rule to paste the new URL.
  • Ask your Workspace admin to confirm incoming webhooks are allowed for your organization.

Some messages are delayed during busy periods

Google Chat limits how fast one webhook can receive messages. When it asks Spacecast to slow down, Spacecast retries automatically, so messages may arrive a little later but are not lost or duplicated.

Still stuck?

Email support@ean-solutions.com with your Jira site URL, the rule name, and, if a message did not arrive, the issue key and time. Do not include the webhook URL.

12. Data and security

Spacecast runs entirely on Atlassian Forge. Rules and the delivery log are stored in Forge hosted storage for your site, and webhook URLs are kept in encrypted Forge secret storage. EAN Solutions does not run its own servers or databases for Spacecast. Space messages go only to chat.googleapis.com, to the webhooks you configure. Personal notifications are sent through the Google Chat API as the Spacecast Chat app, to people who connect their Google account. Digest rules keep a short summary of each update (no comment text) until the digest is sent, for at most 8 days. See the privacy policy and data processing addendum.

13. Uninstall

In Jira, go to Settings > Apps > Manage apps, find Spacecast, and choose Uninstall. Notifications stop immediately, and Forge deletes the app's stored data under Atlassian's retention policy. You can also delete the webhooks in Google Chat.
